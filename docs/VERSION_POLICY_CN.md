# 版本编号与发布规则

本仓库在源仓库 `Wei-Shaw/sub2api` 的版本基础上维护定制功能。所有新发布版本统一使用四段编号：

```text
vA.B.C.D
```

- `A.B.C` 是母版本号，取自本次已经合并的源仓库 `backend/cmd/server/VERSION`。
- `D` 是子版本号，表示 `NieTen/sub2api` 在该母版本上的定制发布次数。
- Git 标签固定使用小写 `v`，程序内的 `VERSION` 文件不带 `v`。

例如，源仓库版本是 `0.2.4`，本仓库在合并后首次发布定制功能，版本就是 `v0.2.4.1`。

## 递增规则

1. 源仓库母版本没有变化时，本仓库每次发布代码更新都将子版本加一，例如 `v0.2.4.1`、`v0.2.4.2`。
2. 源仓库母版本发生变化并完成合并后，前三段改为新的母版本，子版本从 `1` 重新开始。例如，从 `v0.2.4.3` 合并源仓库 `0.2.5` 后，发布 `v0.2.5.1`。
3. 文档、配置或构建脚本的改动只要进入正式发布，也视为本仓库代码更新，需要增加子版本。
4. 不跳号、不复用标签、不在发布后由流水线改写 `VERSION` 文件。

## 合并与发布顺序

1. 使用 `--no-tags` 获取并合并 `Wei-Shaw/sub2api:main`，避免源仓库与本仓库同名标签互相覆盖。
2. 解决冲突并确认现有定制功能仍然存在。
3. 按上面的规则确定版本，并先把 `backend/cmd/server/VERSION` 改为完整的四段版本。
4. 完成测试和构建，将合并结果与版本文件提交到 `main`。
5. 在该提交上创建同名 annotated tag，例如 `v0.2.4.1`，然后推送 `main` 和标签。
6. 发布流水线校验标签格式、`VERSION` 内容、母版本递增和子版本连续性。校验通过后才生成压缩包、Docker 镜像和 GitHub Release。

## 发布产物

GitHub Release、压缩包文件名、程序显示版本以及 Docker 精确标签都使用四段版本，例如：

```text
Sub2API 0.2.4.1
sub2api_0.2.4.1_linux_amd64.tar.gz
ghcr.io/nieten/sub2api:0.2.4.1
```

GoReleaser 内部会收到一个临时的标准 SemVer 标签以完成构建；该标签不会发布，也不会出现在用户可见的产物名称中。
