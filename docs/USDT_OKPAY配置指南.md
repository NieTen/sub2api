# USDT 与 OKPay 配置指南

本功能从定制版本 `v0.2.11.2` 开始提供。`v0.2.11.1` 不包含原生 OKPay 和 TRC20 直收服务商。

`v0.2.11.3` 起支持 TRC20 免密钥公共查询，并修正 OKPay 商户请求的表单编码与业务错误提示。

`v0.2.11.4` 起新建 TRC20 订单使用两位小数的实际到账金额，并在 OKPay 服务商卡片提供只读认证诊断。

`v0.2.11.5` 提供 OKPay 默认 HMAC-SHA256、旧订单协议兼容及三组认证诊断。

## 配置入口

管理员进入「系统设置 → 支付设置」，打开「启用支付」，在「启用的服务商」中勾选需要的 OKPay 或 USDT（TRC20），保存支付设置。随后在「管理服务商」区域添加对应服务商实例，并启用该实例。

「USDT / 人民币费率」位于同一页。兜底费率需要点击该区域自己的保存按钮，表示 **1 USDT 对应多少人民币**，与余额充值倍率分别设置。

## USDT（TRC20 直收）

添加「USDT（TRC20 直收）」实例，填写：

- TRON 收款钱包地址（必填）：有效的、以 `T` 开头的 TRON 主网地址。
- TronGrid API Key（选填）：不填即可使用公共查询；有 Key 时可填写以提高查询配额。

系统内置官方主网节点 `https://api.trongrid.io`，无需填写 API 地址。公共查询仍通过节点接口读取链上数据，可能受到按 IP 的频率限制；系统会控制请求频率，并在节点限流或故障时自动延后重试，因此到账确认可能延迟。

编辑已有实例时，密钥输入框留空会保留已保存的 Key。需要切换为公共查询时，勾选「清除已保存密钥，改用公共免费查询」后保存；已有待支付订单继续按原钱包和金额核验。

服务端查询已确认的主网 USDT 转账，按订单收款地址、精确金额和有效时间匹配后自动入账。系统不需要钱包私钥。

付款页中的「实际到账金额」是收款钱包必须收到的数额。新订单保留两位小数，优先使用汇率换算后的基础金额；同钱包该金额已被使用时，按 0.01 USDT 递增选择最小未使用金额，最多增加 0.99 USDT。订单列表、付款页及复制按钮均使用最终分配金额。

为防止旧订单的延迟转账进入其他用户订单，历史金额不会重新分配。同钱包从基础金额到增加 0.99 USDT 的 100 个候选全部使用后，系统明确拒绝继续下单，需要更换充值金额或收款钱包。两个服务商实例使用同一钱包时也共享此唯一约束。

升级前已创建的六位小数订单继续按原金额付款和核验。请保留收银台显示的全部小数位；转出平台的手续费需要另行承担，应以平台显示的到账金额核对，不能只看转出账户扣款金额或自行四舍五入。

## OKPay

添加「OKPay」实例，填写商户 ID、商户 Token 和回调基础地址。默认 API 基础地址为 `https://api.okaypay.me/shop`，回调基础地址使用本站可从公网访问的 HTTPS 地址。

异步通知路径为 `/api/v1/payment/webhook/okpay`，支付完成返回路径为 `/payment/result`。用户通过 OKPay 收银台支付 USDT；商户侧币种必须与订单一致。

「签名算法」默认选择推荐的 HMAC-SHA256，对应配置 `signatureAlgorithm=hmac_sha256`；服务商配置缺少该字段时也使用新协议。只有明确需要原附件协议时，才选择旧 MD5，对应 `signatureAlgorithm=legacy_md5`。已显式保存的旧协议配置会保留。

新协议在下单、查单请求中加入 `timestamp`、随机 `nonce`，将原始 Token 作为 HMAC-SHA256 密钥；请求仍使用 `application/x-www-form-urlencoded`，新协议回调要求 JSON 对象。成功响应兼容 `status=success` 与业务代码 `200`、`10000`，并继续校验订单、商户、币种及金额。未知错误仅显示通用提示和安全业务代码，不直接展示上游原文。

每笔新订单通过快照字段 `signature_algorithm` 固定协议。历史订单缺少该字段时仍按 MD5 查单和验签，与实例配置缺字段时默认 HMAC 的规则不同。切换实例算法不会改变旧订单协议；认证失败不会自动降级，创建支付失败不会自动重试。

出现认证失败时，可点击已保存 OKPay 实例的「诊断认证」，对照当前配置、Go 模拟的旧 PHP 请求及 HMAC-SHA256 三组结果。诊断固定使用同一份保存配置，总时限为 35 秒，仅查询余额接口，不创建订单或转账。页面显示固定原因分类及可选安全 HTTP 状态、业务代码，不显示 Token、签名或商户余额。

2026 年 10 月 1 日，用户提供本机真实只读结果：同一组凭据访问同一余额接口，旧 MD5 表单和 JSON 请求均为 HTTP 200、身份认证失败；HMAC 表单为 HTTP 200、业务代码 `200`、认证成功。ID 和 Token 的空白及不可见字符检查均为 `false`。这已确认该商户余额认证的新协议有效；真实下单、支付、查单和回调尚未测试。详细证据、三组结果含义和本机 PHP 诊断方法见 [OKPay 认证排查](OKPAY认证排查.md)。

## 汇率与订单追溯

原生 OKPay 和 TRC20 直收共用 USDT / 人民币换算。系统启动后采集报价，此后每 30 分钟采集一次，采用 OKX 返回的前 10 个有效出售价格的中位数。获取失败或报价过期时使用管理员配置的兜底费率；实时与兜底均不可用时停止创建相关支付订单。

人民币应付金额包含本站配置的充值手续费，然后除以订单锁定的人民币 / USDT 汇率，向上取到两位小数。比如人民币应付 10 元、汇率为 7.20 时，基础应付为 1.39 USDT；TRC20 最终还需按订单显示的精确到账金额支付。充值到账的账户余额仍按「余额充值倍率」计算。

「订单管理」显示最近 72 小时的汇率图。每笔新订单保存下单时的费率、来源和人民币金额，使用兜底时明确标注；历史订单不会用当前行情重新计算。新安装没有历史数据时，图表会随实际采集逐步形成。

OKPay 和 TRC20 直收暂不提供自动退款，退款需由管理员在线下处理。
