# 管理员模型检测

模型检测已直接写入当前项目源码：后端使用标准库 Go 改写 ModelTrace 的完整数字指纹算法，并增加本项目独立实现的轻量能力题。服务启动后由后台任务执行，不需要另行部署 ModelTrace、Python、Node.js 或外部检测服务。

## 入口与权限

- 管理员菜单中的“模型质量检测”，地址为 `/admin/model-detection`。
- 管理员账号列表中的“模型检测”列，展示各账号的最近检测结果，并为每个账号提供“立即检测”和“账号检测历史”入口。
- 模型检测计划、手动运行、账号历史和详细结果均只对管理员开放。

账号列表展示的是各账号最近一条检测结果。一个账号配置多个模型时，可在独立页面中按计划查看状态，并在该账号历史记录中查看每次检测所用模型。

## 手动检测与定时计划

选择需要检测的账号和模型。手动检测和新建定时计划都支持一次选择多个模型，每批最多 20 个不同模型。模型可以从账号支持的列表选择，也可以填写上游实际接受的模型名称；所选模型自动作为本次指纹比较的参考，不需要另行填写参考模型。检测通过该账号原有认证、代理、模型映射和协议发出请求，适用于文本对话及推理模型；图片、音频、视频等非文本模型不参加此题组。

批量操作会分别列出成功和失败的模型；成功项保持已创建或已排队状态，可仅重试失败项。新建计划时不会重复建立同账号、同模型的计划；手动检测可复用已有计划，但该计划正在排队或检测时不会重复追加任务。

每个账号、每个模型对应一个计划。可随时手动运行，也可启用以下任一种周期：

1. 每隔指定分钟执行，范围为 1～10080 分钟。下一轮从本轮完成时重新计算，避免前一轮尚未完成就重复请求。
2. 每天指定时间执行，采用计划填写的 IANA 时区，例如 `Asia/Shanghai`，不依赖服务器本地时区。

同一计划同时最多有一个排队或运行任务；整个服务集群最多同时执行两轮。暂停计划会停止后续自动安排，手动检测仍可按需发起。服务中断或执行超时的任务会记录为错误，不自动重放可能已经计费的请求。

每个模型正常完成一轮需要 **4 次模型请求**：三次数字指纹挑战，以及一次包含十道能力题的 JSON 答卷。每次请求最长等待 **600 秒**，整轮最长 **41 分钟**，任务租约为 **42 分钟**。检测不通过降低推理参数来缩短耗时；数字指纹长整数序列和能力题可能比普通连通性测试明显更慢。

请求使用所选账号的额度，可能产生费用；既有上游协议的恢复机制可能产生额外请求。多选模型会分别执行完整的一轮检测。每分钟执行会比每天执行明显增加额度消耗，请根据需要设置周期。刷新检测页面、查看历史和查看详情不会请求模型。

## 能力得分和基线

十道能力题涵盖算术、余数、递推数列、排列、逻辑、文本指令执行、分数、条件循环、容斥和概率。题型及难度范围固定，每次更换数字或文本参数；答案由代码计算，不使用其他模型充当裁判。

每题十分，总分为 0～100 分。每个计划的首个成功结果自动建立能力历史基线；随后计算“基线分数减本次分数”。当下降分数达到计划配置的阈值时，显示“疑似能力下降”。首次没有历史基线，不能据此判断下降；单轮波动也不能证明模型被替换或总体能力发生变化。

页面不提供手工参考模型或重设基线操作。修改计划模型或更新检测版本后，不会继续套用不兼容的旧基线，而由该版本首个成功检测自动建立新基线。每条历史记录保存当轮计划快照和版本，之后编辑计划不会改写历史证据。

网络失败、上游拒绝或限流、输出截断、不支持文本、无效 JSON、缺失题号及重复题号属于检测错误或无法判断，**不会当作零分或能力下降**。完整且可解析的答卷中的错误答案按题扣分。数字指纹结果与能力得分分别展示；指纹不足时也不会伪造模型身份结论。

## 模型指纹的含义

ModelTrace 比较模型直接生成长整数序列时的统计偏好。当前保留完整的频数特征、有序分块特征、环境干扰投影、模型中心匹配和校准 softmax，不是读取接口返回的模型名称来判断。

内置指纹库共有 16 个候选：

| 家族 | 候选模型 |
| --- | --- |
| GPT | `gpt-5.4`、`gpt-5.5`、`gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna`、`gpt-6-astra`、`gpt-6-sol`、`gpt-6-luna` |
| Claude | `claude-haiku-4-5-20251001`、`claude-sonnet-4-6`、`claude-sonnet-5`、`claude-opus-4-6`、`claude-opus-4-7`、`claude-opus-4-8`、`claude-opus-5`、`claude-opus-5-5` |

系统直接使用所选模型名称作为参考模型，判断数字指纹是否与同名库内候选相似。测试库外模型时仍可以评估能力题，但不应把“最接近某候选”当作实际身份认证。候选概率是**闭集概率**：未收录的模型也可能获得很高的某候选相似度。系统提示词、采样参数、协议转换和提供方环境均可能影响结果。

数字指纹只能提供相似或不一致的线索，不能直接测量“智商”，也不能证明欺诈、模型被替换或推理额度被降低。能力题的“疑似下降”同样只表示这组题相对于历史基线的表现变化，可结合多次历史结果核对。

## 运行状态、历史与详情

独立页面展示所有排队或运行中的检测、最近十条完成记录及其统计，包括正常、疑似下降、错误和平均能力分。平均分只纳入成功完成的能力答卷。

选择账号可查看该账号的分页历史。点击详情可查看本次题目、模型回答、逐题标准答案与判分、指纹候选列表、完成状态，以及每次请求的耗时和超时限制。执行时计划快照同时保存在历史记录中，供接口查询。每个计划默认保留 100 条历史，可设置为 100～1000 条；当前基线所对应的证据会额外保留。

每次发出模型请求前先保存题目。请求失败或超时时，会保留已返回给检测任务的部分回答、实际耗时和错误信息，方便区分尚未收到回答与回答中途断流；这些不完整回答不参加评分。进程意外退出时，先前保存的题目仍可查看，但尚未返回给检测任务的流式片段无法保证保存。历史记录中的模型文本经过敏感信息脱敏。
